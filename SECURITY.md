# Security Policy

## Supported versions

Until the first public release, security fixes are developed on the current main branch. The planned first public version is `0.1.x`.

## Reporting a vulnerability

When the public GitHub repository is enabled, prefer GitHub's private vulnerability reporting / Security Advisory flow. Do not include credentials, private browser data, or exploit payloads containing real secrets in a public issue. If private reporting is temporarily unavailable, open a minimal public issue asking for a private contact path without disclosing the vulnerability details.

Useful reports include the affected tool/path, OpenCode version, Windows version, reproduction against dummy/local data, expected security boundary, and whether workflow replay or attach mode is involved.

See `docs/SECURITY-MODEL.md` for trust boundaries and explicit non-goals.
